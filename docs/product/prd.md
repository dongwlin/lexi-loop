# LexiLoop 产品需求（PRD）

> 状态：本文描述已交付 MVP 的现行产品基线；阶段完成状态与后续规划见 [roadmap.md](roadmap.md)。MVP 完成不代表下列边界自动失效。

> 本文档回答「现在这个产品是什么」：为什么做、解决什么问题、用户如何操作、核心业务规则与 MVP 边界。它不包含算法公式与数据库字段——那些是技术实现细节，见 [architecture/overview.md](../architecture/overview.md) 及其下游文档；「以后准备怎么长」的版本阶段规划（MVP → V2 → V3）见 [roadmap.md](roadmap.md)；词典数据方案入口见 [dictionary/overview.md](../dictionary/overview.md)。

## 1. 项目目标

开发一个用于管理和复习英语生词的系统。

这个系统解决两个问题：

1. 将阅读、做题过程中遇到的生词快速导入系统。
2. 根据单词被重复遇到的次数，以及复习时的掌握情况，决定它未来以多高的频率出现。

最终形成一个随导入与复习持续变化的个人生词库：遇到的越多、越记不住的词，越会主动出现；已经掌握的词逐渐少出现。

## 2. 核心循环

整个系统的运行逻辑是一个反馈闭环：

```text
阅读 / 做题
↓ 发现生词
↓ 批量导入
↓ 同一单词再次被遇到 → 遇词次数 + 1
↓ 系统重新评估复习优先级
↓ 加权随机抽取单词
↓ 主动回忆（先想后看）
↓ 记得 / 不记得
↓ 更新掌握程度与复习优先级
↓ 下一次复习
```

即：系统持续根据「遇词次数、复习表现、距离上次复习的时间」调整每个单词的复习优先级，自动决定下一轮优先复习哪些单词。这些因素如何组合成具体算法，属于技术实现，见 [review/algorithm.md](../review/algorithm.md)。

## 3. 导入方式

提供一个多行文本输入框，用户直接粘贴生词列表，例如：

```text
apple
constrain
elaborate
ambiguous
derive
```

基本规则：

- 每行一个英语单词
- 自动忽略空行、去除首尾空格
- 统一转为小写进行匹配
- 同一次粘贴中出现重复单词时照常计数
- 不同词形（如 `derived` / `deriving`）会归并到同一个词条，次数累计在原形词上（词形机制见 [dictionary/normalization.md](../dictionary/normalization.md)）

点击「导入生词」后系统写入生词库，并反馈导入结果（新增几个、已存在几个、累计遇词几次），让用户确认重复单词被正确处理。

## 4. 遇词次数：重要性的信号

生词不能按「唯一值」去重，原因在于：

> 一个单词被用户反复遇到，本身就是这个单词重要程度的一种信号。

例如第一次导入 `constraint`，系统记下：遇词 1 次。过几天再次导入 `constraint`，不创建新记录，而是累计为：遇词 2 次，继续遇到则为 3 次。

因此每个生词都需要记录「用户在实际英语材料中遇到它的次数」，次数越高，越值得优先掌握。系统需要记录遇词次数、每次复习的记得 / 忘记结果、最近复习时间等学习状态（这些状态如何存储属于技术设计，见 [architecture/data-model.md](../architecture/data-model.md) 与 [dictionary/data-model.md](../dictionary/data-model.md)）。

## 5. 复习时展示释义

复习时用户需要看到单词的含义，释义有两个来源：

1. 系统自动从词典数据补全。
2. 用户手动修改为自己能理解的表达。

用户修改只影响自己复习时看到的释义，不会改动客观词典数据本身（见 [dictionary/data-model.md](../dictionary/data-model.md)）。

## 6. 一轮复习

用户进入「开始复习」后先选择本轮复习数量，例如 10 / 20 / 30 / 50 个，或自行输入一个数字。

系统从整个生词库中抽取对应数量的单词。抽词在本轮开始前一次性完成，本轮只复习这一批词，中途不换词。

## 7. 加权随机抽词

不同单词拥有不同的复习优先级，抽词采用加权随机，而不是均匀随机或简单取前 N 个：

- 优先级高的单词更容易被抽到；
- 低优先级单词仍保留一定概率被抽中；
- 抽词保留随机性，避免系统永远只复习最困难的那几个单词。

权重只影响出现概率，不保证一定被抽中。

## 8. 复习交互：先回忆，后看答案

每次复习一个单词：

1. 页面只显示单词本身（如 `ambiguous`），隐藏释义。
2. 用户先在脑中主动回忆它的意思。
3. 点击「查看释义」。
4. 用户判断自己刚才是否回忆成功，选择「记得」或「不记得」。

先回忆再看答案，判断的是自己刚才是否真的记住，而不是凭眼熟作答。

## 9. 一轮结束与结果

用户选 30 个单词复习完后，进入总结页面，显示本轮总计、记得、不记得与正确率，并分别列出记得与不记得的单词。

不记得的单词自动提高后续复习优先级，方便用户下一轮优先处理。

## 10. 掌握程度与复习优先级是两个指标

产品面向用户展示两个不同概念：

- **掌握程度**（0–100）：0–20 非常陌生，20–40 陌生，40–60 一般，60–80 熟悉，80–100 已掌握。
- **复习优先级**：决定这个单词下一轮被抽中的概率。

两者不同：一个单词可能已掌握（例如 80 分以上），但如果很久没有复习，它的复习优先级仍会升高。

## 11. 第一版 MVP

### 包含

生词管理

- 多行批量粘贴导入
- 重复导入累计遇词次数
- 词形归并
- 导入后自动补全基础词典信息：原形、音标、词性、中文释义（数据源与流程见 [dictionary/overview.md](../dictionary/overview.md)）
- 生词库列表
- 查看与编辑复习释义（只影响个人）
- 删除生词

复习

- 设定本轮复习数量
- 加权随机抽词
- 单词正面 → 查看释义 → 记得 / 不记得
- 一轮结果汇总与错误词清单

统计

- 每词展示遇词次数、复习 / 记得 / 忘记次数
- 掌握程度展示
- 复习优先级展示
- 每轮复习结果统计

### 不包含

- 完整间隔重复算法（SM-2、FSRS 等）——第一版只跑通「导入 → 遇词累计 → 加权抽词 → 主动回忆 → 反馈 → 更新优先级」的核心循环
- 自动「到期复习」提醒模式——第一版只做用户主动发起的复习
- 词典增强能力（音频、英文释义、例句、同义词 / 反义词、AI 整理、多词典融合），词典相关能力的阶段边界见 [dictionary/enrichment.md](../dictionary/enrichment.md)
- 多用户与账号体系——第一版按个人使用设计

MVP 之后的能力演进（V2 / V3）见 [roadmap.md](roadmap.md)。
