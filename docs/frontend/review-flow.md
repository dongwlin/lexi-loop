# 复习与生词页面交互（Review Flow）

> 本文档定义前端页面结构、页面状态、复习 UX、键盘操作与关键交互反馈。页面背后调用的接口契约见 [api/words.md](../api/words.md) 与 [api/reviews.md](../api/reviews.md)；释义展示的取值规则见 [dictionary/data-model.md](../dictionary/data-model.md)。

## 0. 前端项目位置

前端应用位于 `apps/web/` 目录下，是一个 Vue 应用。项目采用 pnpm monorepo 架构，详细说明见 [architecture/overview.md](../architecture/overview.md)。

## 1. 页面结构

当前包含六个业务页面，并提供根路径重定向与未知路由兜底：

```text
/
├─ /words          生词库
├─ /words/:id      生词详情
├─ /import         导入生词
├─ /review         开始复习
├─ /review/result/:session  本轮复习结果（对应具体 Session）
└─ /about          关于（版本信息与源码仓库链接）
```

`/` 重定向至 `/review`，未知路径展示 404 页面。关于页展示版本信息与源码仓库链接（外链新标签打开），版本数据契约见 [api/meta.md](../api/meta.md)。`/statistics` 和 `/settings` 尚未实现，新增时先在 [Roadmap](../product/roadmap.md) 明确范围。

## 2. 导入页面 `/import`

### 页面目标

快速把阅读、做题过程中整理出来的生词粘贴进去。

核心界面：

```text
┌────────────────────────────────────────┐
│ 导入生词                                │
│                                        │
│ 每行输入一个单词                         │
│                                        │
│ ┌────────────────────────────────────┐ │
│ │ ambiguous                          │ │
│ │ constrain                          │ │
│ │ derive                             │ │
│ │ subtle                             │ │
│ │ constrain                          │ │
│ └────────────────────────────────────┘ │
│                                        │
│ 共识别 5 行                             │
│                                        │
│              [ 导入 ]                  │
└────────────────────────────────────────┘
```

### 前端解析

用户输入后，前端先做标准化：trim、lowercase、移除空行。**不要先去重再提交**——重复单词本身代表用户遇到了多次。可以在前端聚合成带次数的列表再提交，让请求更精简：

```json
[
  { "word": "ambiguous", "count": 1 },
  { "word": "constrain", "count": 2 },
  { "word": "derive", "count": 1 },
  { "word": "subtle", "count": 1 }
]
```

## 3. 导入结果反馈

导入完成后给用户一个简单反馈，让用户确认系统正确处理了重复单词：

```text
导入完成
新增单词：3
已有单词：1
本次遇到次数：5

ambiguous    新增
constrain    已存在 +2
derive       新增
subtle       新增
```

## 4. 生词库 `/words`

用于管理所有已经导入的单词，建议采用表格：

| Word | 释义 | 遇到 | 复习 | 遗忘 | 掌握度 | 优先级 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| ambiguous | 模棱两可的 | 6 | 12 | 7 | 33% | 8.62 |
| constrain | 限制 | 4 | 9 | 2 | 72% | 4.71 |
| derive | 推导；获得 | 2 | 8 | 1 | 85% | 3.12 |

行的主体是 `user_words`（遇词、复习、遗忘、掌握度、优先级），释义列展示 effective review meaning（取值规则见 [dictionary/data-model.md](../dictionary/data-model.md)），来自关联的 `dictionary_entries`。掌握度与优先级两列的数据来自列表 DTO 的 `masteryScore` / `reviewWeight`（[api/words.md](../api/words.md) §3，D011：由服务端动态计算，前端只展示不复算），分别显示为百分比与权重数值。

第一版只需要搜索、查看、编辑释义、删除。排序以后再加。

## 5. 单词详情

点击一个单词后，打开详情页：

```text
ambiguous
adj. 模棱两可的；含糊不清的；有歧义的

────────────────────
遇到次数        6
复习次数        12
记得次数        5
忘记次数        7
当前掌握度      35%
当前复习优先级  8.4
上次复习        2026-09-03 18:20
```

释义部分展示 effective review meaning，并标注「自定义」当用户修改过自己的复习释义。释义文本保留原始换行，同时允许长文本按容器宽度自动折行；对旧版导入器留下的 raw 释义，展示时兼容其中的字面量 `\n`，无需重新导入词典。以后还可以加入最近复习历史。

## 6. 开始复习页面 `/review`

未开始状态（2026-09-07 定稿）：

```text
今天想复习多少个单词？

[ 10 ] [ 20 ] [ 30 ] [ 50 ] [ 自定义 ]

[ 开始复习 ]
```

预设数量与「自定义」位于同一组选项，「自定义」紧跟 `50` 之后。点击「自定义」后，仅该选项原地替换为数字输入框——按钮与输入框占用同一固定宽度槽位（替换前后占位一致，flex-wrap 的换行条件不因替换而变化，临界视口宽度下也不跳动），输入有效数量后立即作为当前选中的复习数量，无独立的自定义输入区域，也没有「确认」按钮；点击「开始复习」时直接使用当前输入值。输入无效（空 / 非正整数）时开始就地提示「请输入正整数」并阻止开始（错误经 `aria-invalid` / `aria-describedby` 与输入框关联，交互与可访问性规范 §8.4），再次输入即清除，开始时仍无效会重新提示；数量超过可复习生词量的截断提示仅在当前选中的数量有效时显示。输入框以 `aria-label` 提供可访问名：数量选项行是选择器而非表单场景，不适用同规范 §8.1 的持久可见 Label 要求（2026-09-07 裁决，加可见标注会破坏「仅该选项原地替换」）。

自定义输入框在该模式下持续显示 `primary` 高亮边框（失焦仍保留）；键盘聚焦时额外显示独立焦点轮廓。进入校验错误态时，错误色边框与焦点轮廓优先于选中高亮，并保留关联的错误文字；浅色与深色主题共用语义色。切回预设数量后，输入框消失，由对应预设按钮表达选中态。

数量选择本地持久化（2026-09-07 定稿）：上次的选择——预设值，或自定义模式及其输入的数量——在下次进入复习页时恢复（自定义恢复为选中的自定义输入框并带回上次数量）；无记录或数据非法时默认选中 30。每次有效输入即时持久化，输入回退到空 / 非法值时停留在最后的有效值；自定义与预设来回切换时，再次点击「自定义」带回上一次输入的数量并即时生效、同步持久化，屏幕选中态与本地存储保持一致。

第一版不需要自动给建议值。用户输入的数量超过当前可复习生词数时，提示「当前只有 N 个可复习生词，本轮将复习全部 N 个」并允许开始（服务端按 `min(count, available)` 截断的契约见 [api/reviews.md](../api/reviews.md)）。

### active session 恢复

重新进入 `/review` 时若检测到存在 `active` 的未完成一轮，展示「继续复习」（回到原进度，如 12/30）与「放弃本轮」两个选择，由用户明确决定，系统不自动进入也不自动放弃（生命周期规则见 [review/data-model.md](../review/data-model.md)）。

「继续复习」从本地快照与服务端逐词结果对齐后的首个未答项续答；进入复习区域后把焦点移入该区域，保证 Space / 1 / 2 快捷键立即可用（§10）。

「放弃本轮」调用 `POST /api/v1/reviews/:sessionId/abandon`（契约见 [api/reviews.md](../api/reviews.md) §6）由服务端把该轮标记为 `abandoned`，成功后清除本地恢复快照并回到数量配置视图；请求失败时（网络 / 5xx）保留快照与恢复入口，展示可重试的错误提示；返回 404（session 已不存在）或 422（该轮已结束）时视为快照失效，清除后回到数量配置视图。

## 7. 复习页面

每张卡首次只显示单词和「不认识 / 认识」，用户先主动回忆再判断，无独立「查看释义」步骤。

```text
12 / 30
              ambiguous
       先回忆这个单词的意思
        [ 不认识 ]    [ 认识 ]
```

点击任一判断后立即揭示释义，仅在前端内存中保存暂定结果，不调用提交 API。

```text
              ambiguous
        adj. 模棱两可的；含糊不清的；有歧义的
        [ 不认识 ]    [ 下一词 ]
```

初选「认识」时显示「不认识」修正入口：只能把暂定结果从 remembered 改为 forgotten，修正后仍停留在当前释义页，并隐藏修正按钮。初选「不认识」时直接只显示「下一词」，不允许看过释义后向上修正。

点击「下一词」才提交最终结果；提交期间禁用按钮与快捷操作。成功后进入下一卡并清空暂定结果，最后一题成功后进入结果页。失败时保留当前卡、释义和结果，展示重试提示；第一次提交后锁定本卡结果，重试发送相同值（响应丢失时服务端可能已计数）。API 的一次性提交契约保持不变，见 [api/reviews.md](../api/reviews.md) §3。

复习交互区按「单词 / 提示或释义 / 操作 / 快捷键提示」分槽布局。提示与释义共用响应式最小高度，常规一行、两行释义不改变卡片高度或按钮垂直位置；操作区保留两列，「不认识」在左，「认识 / 下一词」在右，隐藏修正按钮后不移动「下一词」。快捷键提示预留换行空间。长单词和超长释义允许自动换行并自然撑高，不裁切内容。

暂定结果不写入本地快照；刷新 / 重新进入后仍从服务端首个 pending item 的未揭示阶段继续。

复习释义按义项分行，保留译文中的实际换行，并兼容旧 ECDICT 释义中的字面量 `\n`；长文本按可用宽度自动折行。新开一轮与恢复本地快照使用相同的展示规则，转换仅作用于展示文本，不改写快照或提交数据。

## 8. 一轮复习只复习固定一批

开始一轮时创建 `review_sessions`，并从词库中一次性抽取本轮单词，不要在每次作答后重新随机抽词——否则 30 个的一轮可能反复抽到同一个单词。

抽取采用加权、不放回抽样，一轮开始时选出 30 个不同的单词，本轮只复习这 30 个。

以词库 A、B、C、D、E、本轮抽 3 个为例，结果应是 A、D、B 这类三个不同的词，而不是 A、A、D：同一轮重复测同一个词价值低。A 即使权重很高，也只是在下一轮更容易再次出现。（抽样算法见 [review/algorithm.md](../review/algorithm.md)。）

## 9. 复习结果页

```text
本轮完成 ✓
30 个单词
21 记得
9 不记得
正确率 70%
```

重点展示「需要加强」的单词列表，并提供「再来一轮」「回到生词库」两个按钮。「只复习本轮忘记的单词」属于后续规划，阶段与优先级统一见 [Roadmap](../product/roadmap.md)。

已完成轮次的结果首次显示且可再次开始时，结果页在页面级导航焦点处理之后，将焦点移到「再来一轮」按钮。Enter / Space 使用按钮原生行为，Tab 可继续访问「回到生词库」；同一轮次的后台刷新不重复抢焦点。加载中、加载失败、未完成 / 已放弃或总词数为 0 时不聚焦该按钮；开始失败仍聚焦错误提示。

「再来一轮」的行为（2026-09-07 定稿）：以上一轮的实际词数（结果页 session 汇总的 `total`）作为新一轮数量直接开始，等价于在 `/review` 输入该数量并开始（服务端仍按 `min(count, available)` 截断，D009）；开始成功后跳转 `/review` 直接进入第一题，不经数量配置页——用户刚完成一轮，此时点击该按钮的意图就是继续练，数量调整可通过导航进入 `/review` 配置页完成。开始请求失败时（如可复习生词为 0 的 `BASE.BIZ.USER_DISABLED`、网络异常）留在结果页展示错误与重试。开始后本轮中途刷新 / 退出再进入 `/review`，恢复仍按 §6 由用户选择继续或放弃。「回到生词库」跳转 `/words`。

## 10. 前端状态机与键盘操作

复习页面的 `ReviewMode` 仅包含 `idle`、`recalling`、`revealed`：

```text
idle → recalling → revealed ── 提交成功 ──→ recalling（下一卡）
                      └──── 最后一题提交成功 ──→ 跳转结果页
```

- **idle**：数量选择阶段。
- **recalling**：只显示单词，按钮「不认识 / 认识」；选择暂定结果后进入 revealed。
- **revealed**：显示释义；首次提交前允许 remembered → forgotten 单向修正。提交期间及提交失败后仍保持此模式。

`isSubmitting` 是 revealed 阶段的独立提交状态，不属于 `ReviewMode`。点击「下一词」时同步设为 `true` 并提交 API，禁用按钮与快捷操作，阻止重复提交；请求处理结束时在 `finally` 中重置为 `false`。成功后清空暂定结果，非最后一题 index++ 并进入下一卡的 recalling；最后一题的推进结果为 `finished`，页面跳转 `/review/result/:session`（`finished` 也不是 `ReviewMode`）。失败时保持 revealed、当前卡、释义和结果，解除提交中状态后允许重试。

`submissionStarted` 表示本卡是否已发起过提交，用于锁定最终结果；失败后仍为 `true`，因此重试前不能再修正，重试发送相同结果。它与仅表示提交处理中的 `isSubmitting` 相互独立。

快捷键仅在复习区域内生效，忽略长按重复、输入法组合与带修饰键的事件：

| 阶段 | 按键 | 操作 |
| --- | --- | --- |
| recalling | `1` / `←` | 不认识并揭示释义 |
| recalling | `2` / `→` | 认识并揭示释义 |
| revealed | `Space` / `Enter` | 下一词（提交最终结果） |
| revealed（尚未提交且暂定认识） | `1` / `←` | 修正为不认识 |

revealed 不映射 `2` / `→`。控件上的 Space / Enter 保留原生激活，输入控件不拦截快捷键。页面提示随阶段及可修正状态更新；进入、揭示、修正和推进后焦点回到复习区域，失败后同样恢复焦点以便重试。
