# Agent Log

Agent Log 记录 Agent 已完成的仓库工作，帮助后续 Agent 快速了解近期改动。它是工作流水，不是产品、技术或决策的权威文档。

## 工作前阅读

- 开始会修改仓库的任务前，先打开按文件名排序最新的 `YYYY-MM.md`，阅读文件头部的最近记录。
- 只把日志当作定位相关文档的线索。开始修改前，必须重新阅读相关权威文档和当前文件，不得仅根据日志中的摘要作出设计判断。
- 日志与正式文档冲突时，按根目录 [AGENTS.md](../../AGENTS.md) 的冲突裁决原则处理。

## 记录时机

- 仅在一个工作单元已完成且产生仓库文件变化后记录。
- 纯问答、只读分析、尚未落地的方案、中间命令与工具调用不记录。
- 未完成的工作不得记为完成。如果失败结果对后续工作有持续价值，可以单独记录，但必须标明“未完成”及原因。
- 多 Agent 协作时，只由主 Agent 在整体任务结束后写入汇总记录。

## 文件与排序

- 文件按月命名为 `YYYY-MM.md`。
- 每条新记录插入当月文件的一级标题之后，使月内记录保持时间逆序。
- 时间使用仓库所在时区，格式为 `YYYY-MM-DD HH:mm:ss +08:00`。
- 同一工作单元只写一条记录，应与实际文件变更一同交付。

## 记录格式

```md
## 2026-09-05 16:40:00 +08:00 — 完善复习 API 契约

- 完成：补充提交结果的幂等与归属校验约束。
- 涉及：`docs/api/reviews.md`、`docs/decisions/README.md`
- 验证：检查相关文档引用，未发现冲突。
```

“完成”说明结果，“涉及”列出主要变更文件，“验证”记录已执行的检查。只写摘要和文件引用，不在日志里复制 schema、公式、API 契约或决策正文。
